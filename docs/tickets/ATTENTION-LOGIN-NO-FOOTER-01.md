# ATTENTION-LOGIN-NO-FOOTER-01 — без футера на экране входа в портал

**Статус:** готово к ревью
**Дата:** 2026-10-26
**Ветка:** `TUTORIALS-REACT` (по просьбе: без новой ветки и без worktree)

## Задача

На странице портала `#/attention` убрать футер сайта (контакты, отделы,
ресурсы, адрес, соцсети, копирайт) с экрана входа в аккаунт.

## Решения по уточнениям

- Футер убирается **только с экранов входа**: ввод e-mail, код, пароль,
  восстановление пароля, уведомление «сессия истекла».
- После входа (обзор, договор, банк, документы) футер **остаётся**, как
  сейчас.
- Остальные страницы не меняются: на страницах регистрации футера нет и не
  было, у туториалов свой футер.

## План

1. Футер сайта показывается не по адресу страницы, а по запросу самой
   страницы: `AppShell` (`App.jsx`) рисует `SiteFooter`, только если
   страница попросила его через хук.
2. `AttentionPage` просит футер только в режиме `portal` (после входа). Пока
   проверяется сохранённая сессия (`loading`) и на экране входа (`login`)
   футера нет — так он не мелькает под экраном входа, пока грузится
   страница.

## Что сделано

- `src/components/SiteFooter.jsx` — `SiteFooterContext` и хук
  `useSiteFooter(show)`: страница сама просит футер, при уходе со страницы
  (размонтировании) он снимается.
- `src/App.jsx` (`AppShell`) — вместо проверки адреса (`/attention`) футер
  рисуется, только пока страница его просит.
- `src/pages/attention/AttentionPage.jsx` — `useSiteFooter(view ===
  'portal')`.
- `CLAUDE.md` — описание футера обновлено.

## Проверка

- `npm run build` — без ошибок (ESLint в проекте не настроен).
- Браузер (dev-сервер; для состояния «после входа» — локальный мок-бэкенд
  `devtools/portal-mock-server.mjs`):
  - `#/attention` без сессии — экран входа без футера: тёмная тема 1440px,
    светлая 375px; горизонтальной прокрутки нет;
  - после входа (обзор) — футер на месте;
  - «Sign out» — снова экран входа без футера;
  - со страницы портала после входа на `#/` — футер исчезает;
  - `#/`, `#/registration`, `#/post-signing`, `#/relink` — без футера;
    `#/portal` → `#/attention` (вход) — без футера; `#/tutorials` — только
    его собственный футер.
- Ошибок от изменения нет. В консоли были две 404 на
  `GET /api/portal/contract` — их отдаёт мок-бэкенд, в котором нет этого
  обработчика; с настоящим бэкендом и без входа их нет, к задаче не
  относятся.
- Не проверено: экраны кода, пароля и восстановления пароля по отдельности —
  они внутри того же режима `login`, что и ввод e-mail, поэтому футера на них
  тоже нет.
