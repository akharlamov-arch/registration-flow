# TUTORIALS-AUTH-01 — туториалы только после входа, без Accounting Team в футере

**Статус:** готово к ревью
**Дата:** 2026-10-29
**Ветка:** `TUTORIALS-REACT` (по просьбе: без новой ветки и без worktree)

## Задача

1. Страница туториалов (`#/tutorials`, `#/tutorials/<slug>`) открывается
   только тому, кто вошёл в клиентский портал. Кто не вошёл, того сразу
   отправляет на страницу входа.
2. Убрать из футера в колонке «Departments» пункт «Accounting Team —
   accounting@itrucking.org».

## Решения по уточнениям

- Страница входа — экран входа портала `#/attention`.
- После входа человек попадает на главную портала (`#/attention`, обзор),
  как при обычном входе, а не обратно в туториал.
- «Accounting Team — accounting@itrucking.org» убирается **из обоих
  футеров**: футера портала (`SiteFooter`) и футера страницы туториалов.
  Телефон бухгалтерии в колонке «Contact» («Accounting Team, +1 (916)
  269-4606 ext. 3») остаётся — его не просили убирать.

## План

1. Ключ, под которым портал хранит токен сессии в `sessionStorage`
   (`itrucking-attention-token`), вынести в `src/api/portal.js`, чтобы его
   читали и `AttentionPage`, и проверка на туториалах.
2. Обернуть маршрут `#/tutorials/*` в `App.jsx` проверкой сессии:
   - токена нет — сразу `#/attention` (с `replace`, чтобы «Назад» не
     возвращал на туториалы и не отправлял на вход снова);
   - токен есть — проверить его на сервере (`GET /api/portal/session`, тот
     же запрос, что делает портал), пока идёт проверка, показать заглушку;
     сервер принял — показать туториалы; отказал (сессия истекла) или
     недоступен — удалить токен и отправить на `#/attention`. При
     недоступном сервере токен тоже удаляется: иначе портал сам начинает
     проверять токен и бесконечно висит на заглушке (у него нет обработки
     сетевой ошибки), а так человек видит экран входа.
   - Проверка один раз при входе на страницу туториалов; переходы внутри
     (список ↔ туториал, фильтр категорий) её не повторяют.
3. Удалить пункт из `SiteFooter.jsx` и из `config/site.ts` туториалов,
   вместе с неиспользуемыми строками (`footer.accounting` в
   `translations.js`, `footerAccounting` в `i18n/messages.ts`).
4. Обновить `CLAUDE.md`.

## Что сделано

- `src/api/portal.js` — `ATTENTION_TOKEN_KEY` (`itrucking-attention-token`).
- `src/pages/attention/AttentionPage.jsx` — свой `TOKEN_KEY` заменён на
  импорт `ATTENTION_TOKEN_KEY`, поведение не менялось.
- `src/App.jsx` — компонент `RequirePortalSession` (проверка сессии,
  заглушка `PageFallback` на время проверки, `Navigate` на `/attention`),
  им обёрнут маршрут `/tutorials/*`.
- `src/components/SiteFooter.jsx` — удалена ссылка «Accounting Team —
  accounting@itrucking.org»; `src/data/translations.js` — удалена строка
  `footer.accounting` (во всех 4 языках).
- `src/pages/tutorials/config/site.ts` — удалён e-mail бухгалтерии;
  `src/pages/tutorials/i18n/messages.ts` — удалена строка `footerAccounting`
  (ru/en/uk).
- `CLAUDE.md` — описаны проверка входа на туториалах и изменение футеров.

## Проверка

- `npm run build` — без ошибок (ESLint и TypeScript в проекте не
  настроены).
- Браузер, dev-сервер; для состояния «вошёл» — локальный мок-бэкенд
  `devtools/portal-mock-server.mjs` (конфигурации в `.claude/launch.json`
  добавлялись временно и убраны):
  - без входа `#/tutorials` и `#/tutorials/efs-card-block` → экран входа
    `#/attention`;
  - чистый адрес `/registration-flow/tutorials/efs-card-block` (без `#`) →
    экран входа;
  - вход (e-mail → код → пароль) → главная портала (`#/attention`), не
    туториал;
  - после входа «See all» в блоке туториалов портала → список туториалов
    открывается; прямая ссылка `#/tutorials/efs-card-block` и перезагрузка
    страницы — туториал открывается, сессия сохраняется;
  - подменённый (недействительный) токен → токен удалён, экран входа;
  - бэкенд недоступен, токен есть → токен удалён, экран входа (без
    зависания);
  - «Назад» после переброски не зацикливается: предыдущие записи истории
    с туториалами снова ведут на вход, дальше — обычная история;
  - футер портала и футер туториалов: в «Departments» только General
    Inquiries и Fuel Department; телефон «Accounting Team» в «Contact» на
    месте.
- Консоль: две 401 на `GET /api/portal/session` — это ожидаемый отказ
  сервера на подменённый токен (в dev-режиме React StrictMode делает запрос
  дважды); одна 404 на `GET /api/portal/contract` — в мок-бэкенде нет этого
  обработчика (уже отмечено в ATTENTION-LOGIN-NO-FOOTER-01), к задаче не
  относится. Других ошибок нет.
- Ограничение: сессия портала хранится в `sessionStorage`, то есть в
  пределах одной вкладки. Туториал, открытый в новой вкладке (например,
  средней кнопкой мыши), попросит войти заново — так же, как сам портал.
