# MOBILE-VERSION-01 — убрать список шагов с мобильной версии портала

**Статус:** готово к ревью
**Дата:** 2026-10-12
**Ветка:** `MOBILE-VERSION`

## Задача

На странице портала `#/attention` ([`AttentionPage.jsx`](../../src/pages/attention/AttentionPage.jsx))
в мобильной вёрстке над карточками «Update details» / «Update bank» стоял
список шагов:

- **1** Updated contract details — *Action required*
- **2** Bank account — *Action required*

На телефоне этот список дублирует карточки под ним: он только показывает
статус (`Stepper` с `readOnly`), нажать на него нельзя, а клиент переходит
дальше кнопками «Update». Список нужно убрать с мобильной версии.

Уточнения по задаче:

1. **Ширина.** «Мобильной» считается любая ширина, на которой страница
   собирается в одну колонку: **до 1024px** (брейкпоинт `lg`), т.е. телефоны и
   планшеты. С 1024px боковая колонка становится сайдбаром, и там список
   шагов остаётся как был.
2. **«Documents & policies».** После того как список ушёл, ссылка на библиотеку
   документов оказалась бы первой, над карточками. На мобильном она переезжает
   **под** основной контент, как на скриншоте с iPhone.

## Решение

Изменён один файл —
[`src/pages/attention/AttentionPage.jsx`](../../src/pages/attention/AttentionPage.jsx).
Правка только в разметке, без новых компонентов и без дублирования ссылки на
документы:

| Элемент | Было | Стало |
|---|---|---|
| `<aside>` (боковая колонка) | `lg:sticky lg:top-20` | `order-last lg:order-none lg:sticky lg:top-20`: до `lg` колонка встаёт после контента, с `lg` порядок в DOM прежний (сайдбар слева) |
| `<Stepper>` | всегда виден | обёрнут в `hidden lg:block`: до `lg` не рендерится визуально (`display: none`) |
| Обёртка «Documents & policies» | `mt-3 pt-3 border-t` | `lg:mt-3 lg:pt-3 lg:border-t`: разделитель над ссылкой нужен только под списком шагов, без него на мобильном осталась бы висящая линия |

Логика страницы (`steps`, `lockedStep`, статусы) не тронута, `Stepper.jsx` и
`Overview.jsx` не менялись. Колонка переставлена через CSS `order`, а не
перемещением в DOM, поэтому ссылка на документы существует в одном
экземпляре для обеих раскладок.

## Проверка

`npm run dev` + локальный бэкенд `pijb-phx` (:4000), dev-клиент из тестового
набора, встроенный браузер:

- **375px (мобильный):** списка шагов нет; порядок: AccountBar → заголовок →
  «Update details» → «Update bank» → «Documents & policies». Вычисленные стили:
  обёртка `Stepper` — `display: none`, у `<aside>` — `order: 9999`, у
  обёртки ссылки нет ни линии, ни отступа сверху.
- **375px, вкладки:** «Update bank» и «Documents & policies» открываются,
  кнопка «Back to overview» возвращает на обзор; список шагов не появляется
  ни на одной вкладке, ссылка на документы стоит под контентом.
- **768px (планшет):** то же, что на мобильном.
- **1280px (десктоп):** без изменений: сайдбар слева со списком шагов, ниже
  «Documents & policies» с разделителем (1px `gray-200`, отступы 12px),
  `position: sticky`.
- `npm run build` — без ошибок и предупреждений.

## Замеченное попутно (не в рамках задачи)

- `GET /api/portal/policies` на локальном бэкенде отвечает 404 на preflight
  (CORS-ошибка в консоли): маршрута нет ни в `dev`, ни в `master` `pijb-phx`.
  Это уже известно (см. [`ATTANTION-PAGE-01`](ATTANTION-PAGE-01.md)),
  фронт ловит ошибку в `.catch()` и показывает пустую библиотеку
  «No documents are published yet.» Мобильная правка на это не влияет.
